# 03_Standard_Operating_Procedures.md - Agent Memory Protocol

ဤဖိုင်သည် Cosmos Team ၏ အေးဂျင့်အားလုံး လိုက်နာရမည့် မှတ်ဉာဏ်စီမံခန့်ခွဲမှု ဆိုင်ရာ စည်းကမ်းချက်များ ဖြစ်သည်။

## 🏛️ Folder Pillar System (20/80 Impact)
အေးဂျင့်တိုင်းသည် အောက်ပါ ပင်မအကိုင်းအခက် ၃ ခုကို အခြေခံ၍ မှတ်တမ်းတင်ရမည်-
1. **01_Context/:** ပင်မဗဟုသုတ၊ မူဝါဒများနှင့် ရေရှည်မှတ်သားရမည့် အချက်အလက်များ။
2. **02_Logs/:** နေ့စဉ်လုပ်ဆောင်ချက်များ၊ ဆုံးဖြတ်ချက်များနှင့် အောင်မြင်မှု/ရှုံးနိမ့်မှု မှတ်တမ်းများ။
3. **03_Workflows/:** အလုပ်လုပ်ပုံ အဆင့်ဆင့်နှင့် ပြန်လည်အသုံးပြုနိုင်သော လုပ်ငန်းစဉ်များ။

## 🔢 Naming & Indexing (5-99 Rule)
- Folder နှင့် File တိုင်းကို `01_Name.md` ကဲ့သို့ နံပါတ်စဉ်တပ်၍ သိမ်းဆည်းရမည်။
- ဖိုင်အသစ် သိမ်းဆည်းပြီးတိုင်း `00_Shared/00_Context/00_INDEX.md` တွင် သွားရောက် အပ်ဒိတ်လုပ်ရမည်။

## 🔄 Memory Cycle
- ၁၂ နာရီတစ်ကြိမ် Librarian Skill ကို အသုံးပြု၍ စကားဝိုင်းများကို အနှစ်ချုပ်ကာ သက်ဆိုင်ရာ Folder များသို့ ခွဲခြားပို့ဆောင်ရမည်။
- အနှစ်ချုပ်ပြီးပါက Nolan ထံသို့ Status တိုတိုလေးဖြင့် အကြောင်းကြားရမည်။

## 🛡️ Scalability
- အလုပ်များ ပိုမိုကြီးမားလာပါက `04_`, `05_` စသဖြင့် နံပါတ်စဉ်တပ်ကာ Folder အသစ်များကို တိုးချဲ့နိုင်သည်။
- အသုံးမလိုတော့သော မှတ်ဉာဏ်ဟောင်းများကို `99_Archive/` သို့ ပြောင်းရွှေ့ရမည်။

## 🟢 CRON REGISTRATION & CONFLICT RESOLUTION (MANDATORY)
၁။ **Must Register:** မည်သည့် အချိန်ကိုက်အလုပ် (Cron Job/Schedule) မဆို ပင်မ root ရှိ `CRON_REGISTER.md` ဖိုင်တွင် မဖြစ်မနေ လာရောက်စာရင်းသွင်းရမည်။
၂။ **Check First:** အေးဂျင့်တိုင်းသည် task အသစ်တစ်ခု မပြုလုပ်မီ `CRON_REGISTER.md` ကို အရင်ဖတ်ပြီး လက်ရှိ run နေသော အလုပ်များနှင့် အချိန်တိုက်ဆိုင်မှု ရှိ၊ မရှိ စစ်ဆေးရမည်။
၃။ **Conflict Handling:** အကယ်၍ အချိန်တိုက်ဆိုင်နေပါက (ဥပမာ- RAM အများကြီးသုံးမည့် အလုပ်နှစ်ခု တစ်ချိန်တည်း run ခြင်း) Priority မြင့်သော အလုပ်ကိုသာ ခွင့်ပြုမည်။
၄။ **Kill Switch:** စာရင်းမသွင်းဘဲ သို့မဟုတ် အချိန်တိုက်နေသည့် အလုပ်များကို David မှ တွေ့ရှိပါက အချိန်မရွေး ရပ်နား (Kill/Stop) ပိုင်ခွင့်ရှိသည်။
